# WTC11 MHC guide mapping

Analysis run September 9, 2026 with the existing `mambaforge` environment.

Of **11,253 guide rows with an exact GRCh38 chr6 MHC match, 475 (4.22%)
have no exact 19-nt match in either supplied WTC11 haplotype FASTA**.
The two haplotypes rescue different guides, so neither alone is sufficient.

| Reference searched | MHC guides without a match | Fraction |
| --- | ---: | ---: |
| WTC11 hap1 | 841 | 7.47% |
| WTC11 hap2 | 759 | 6.74% |
| Either WTC11 haplotype | 475 | 4.22% |

The coordinate-based and intended-MHC cohorts both contain 11,253 guides and
have the same overall loss counts. Their positional outputs are saved separately.

## Inputs and method

- `data/wtc11.hap1.mhc_contigs.fa`: one contig, `hap1_h1tg000020l`, 61,671,305 bp.
- `data/wtc11.hap2.mhc_contigs.fa`: one contig, `hap2_h2tg000025l`, 32,322,129 bp.
- Neither supplied contig contains N bases. Both are much longer than the MHC;
  matches are counted over the **entire supplied contig**, not a lifted-over MHC slice.
- The original IGVF library supplies 12,625 valid, unique trimmed 19-mers.
  Spacer IDs are regenerated by sorting sequences and checked against the old
  per-guide summary before joining the cached GRCh38 alignments.
- Alignment repeats `bowtie2 --end-to-end -a --no-unal -f` on each FASTA.
  All NM=0, non-supplementary loci are retained, including secondary alignments.
  There are 10,893 exact alignment records in hap1 and 10,640 in hap2.
- Missing means a GRCh38 exact match with no WTC11 exact match. MHC loss
  statistics use GRCh38 chr6:28,000,000–34,000,000, as in the existing analyses.
- A guide matching both haplotypes is present; summing haplotype locus counts
  does not imply multiple loci within an individual haplotype.
- This is PAM-agnostic exact sequence presence, not a prediction of guide activity.

The workflow reuses the existing guide-lookup and screen-analysis scripts with
an explicit WTC11 label. The new driver implements the summaries, loss profiles,
plots and sequence clustering. It preserves the old 10-kb windows, 10-kb cluster
gap and 100-kb density comparison. Unlike the old loss script, it uses the full
Benjamini–Hochberg adjustment, including the cumulative minimum. It also selects
a GRCh38 locus per guide row using the nearest intended guide coordinate.

## Mapping lookup and inferred explanations

| Mapping class | All library guide rows |
| --- | ---: |
| unique_both | 9,818 |
| non_targeting | 1,262 |
| hemizygous_WTC11 | 554 |
| missing_in_WTC11 | 475 |
| multi_hg38 | 253 |
| outside_WTC11_assembly | 110 |
| hemizygous_assembly_gap | 78 |
| multi_WTC11 | 75 |

These are exclusive classes with the original precedence rules. Independent
flags can overlap: 650 MHC guides match just one haplotype, including 91 flagged
for low local sequence-match coverage. Some fall under a multi-mapping class
rather than the exclusive single-haplotype classes above.

For the 475 missing guides, the inherited flanking-anchor heuristic assigns:

| Inferred explanation | Guides |
| --- | ---: |
| snv_or_small_indel | 381 |
| deletion_in_both_haplotypes | 43 |
| deletion_in_one_haplotype | 30 |
| insertion_in_WTC11 | 21 |

**These are hypotheses, not variant calls.** In particular, 103 missing guides
have `absence_in_assembly_gap=True`, leaving 372 without that flag. This flag
measures the fraction of nearby reference guide sequences found in the assembly;
it does not inspect assembly gaps. Low matching can also arise from concentrated
haplotype divergence or genuine deletions. The long, N-free input contigs do not
justify interpreting the flag as a confirmed assembly gap. Likewise,
`hemizygous_WTC11` means a single-haplotype exact match, not demonstrated
hemizygosity or allele-specific activity. No contig-overlap ambiguity was flagged.

## Spatial losses

Nine populated 100-kb bins have excess loss under the inherited binomial model
with BH q < 0.05. The strongest are chr6:32.5–32.6 Mb (60/100 guides missing;
14.21-fold the global rate) and 32.6–32.7 Mb (51/119; 10.15-fold).
Other flagged bins start at 29.7, 29.8, 29.9, 31.2, 31.3, 32.4 and 32.7 Mb.

These tests describe clustering relative to library density. Nearby guides are
not independent, so the binomial p-values should not be treated as independent
biological replication. The main observed-versus-expected plot uses one y-scale;
a separately saved dual-axis plot has incomparable bar heights across series.

Overall, **42 of 960 top-guide slots (4.38%) at hits are flagged, affecting
27 of 320 screen-specific DHS–gene pairs**. Of these slots, 24 have no exact
match in either WTC11 haplotype, 16 are classified multi_hg38 and 2 multi_WTC11.
Seven of the 24 missing slots carry the low-coverage flag. Slots can repeat the
same guide across different genes or screens; these are not unique-guide counts.

The inherited `relevant_problem` definition includes missing guides even when
low coverage is flagged, and includes GRCh38 multi-mapping as a review flag.
Reference multi-mapping alone does not prove multiple functional WTC11 targets.
Single-haplotype matches are reported separately: 41 hit slots after excluding
low-coverage flags. These results identify pairs for review; they do not establish
that problematic guides cause the hits, or that exact-missing guides cannot act.
The K562 report's conclusion should not simply be transferred to WTC11.

Validation checked all 21,533 exact WTC11 placement records directly against the
FASTA sequences on the correct strand, guide counts and joins, haplotype union,
window and cluster accounting, BH monotonicity, and screen scope. A synthetic
regression check verifies that secondary exact loci survive filtering while
supplementary and mismatch records do not. This verifies reported placements;
it is not an independent exhaustive search for aligner false negatives.

## Audit of other guides in DHSs containing missing, gap-flagged guides (September 10)

Input hashes were checked and both WTC11 local-coverage columns independently recomputed. The 103 guides classified `missing_in_WTC11` with `absence_in_assembly_gap=True` belong to nine DHSs. All library guides assigned to these DHSs were checked, not just top-three screen guides.

The flag is based on unique-locus GRCh38 MHC spacers within ±25 kb of each guide’s reference locus. For a guide missing from both haplotypes, the larger of the two local match fractions must be below 0.5. It measures exact-guide matching, not base-level assembly coverage or a DHS-wide deletion. Different guides query different 19-base sequences, so exact presence can differ within one DHS.

Of the 76 other guides, only 22 are `unique_both` (none has a recorded GRCh38 off-target locus). Four are also missing, 18 have a multi-mapping class, and 32 are single-haplotype matches, including 31 with low-coverage flags. Only **chr6:32609751-32610407** has all seven other guides classified `unique_both`. That is a mapping result, not functional validation.

The inherited `is_problematic` boolean excludes `hemizygous_assembly_gap`. Therefore `is_problematic=False` alone does not establish clean mapping to both haplotypes. For example, chr6:32589565-32590024 has six other guides, all single-haplotype/low-coverage flagged, although none is marked `is_problematic`.
